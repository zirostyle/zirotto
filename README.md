# 🎰 zirotto — 동행복권 자동 구매

로또 6/45 및 연금복권 720+ 자동 구매 봇. 서버 없이 GitHub Actions 로만 동작합니다.

> [!IMPORTANT]
> 동행복권 구매지원 도구이며, 자동구매 설정 시 신중한 확인이 필요합니다.
> **모든 구매 결과 및 예치금 사용 책임은 사용자 본인에게 있습니다.**
>
> **복권 과몰입 및 중독 예방 제도 준수**
> 동행복권이 제공하는 제도(구매 한도, 충전 제한, 이용 시간 등) 범위 내에서만
> 동작하도록 설계되었습니다. 해당 제도를 우회하거나 무력화하는 기능은 없습니다.

## ⚠️ 번호 선택에 대한 정직한 설명

이 프로젝트에는 번호 생성 전략(`src/number_strategy.py`)이 포함되어 있습니다.
**당첨 확률은 높이지 않습니다. 높일 수 없습니다.**

로또 6/45 의 1등 확률은 `C(45,6) = 8,145,060` 분의 1 이며, 어떤 조합을 고르든
정확히 동일합니다. 추첨은 독립 시행이므로 과거 당첨번호, 미출현 기간,
"핫/콜드 번호", 궁합수 같은 것은 다음 추첨에 아무 영향을 주지 않습니다.

그럼 무엇을 최적화하는가 → **당첨됐을 때 실제로 받는 금액(기댓값)** 입니다.

한국 로또 1~3등은 **파리뮤추얼(pari-mutuel)** 방식입니다. 등수별 상금 풀을
그 등수 당첨자 수로 나눠 분배합니다. 따라서 같은 조합을 고른 사람이 적으면
1인당 수령액이 커집니다. (4등 50,000원 / 5등 5,000원은 고정액이므로 무관)

사람들의 번호 선택은 균일하지 않고 강하게 편향되어 있습니다:

| 편향 | 내용 |
|---|---|
| 생일 편향 | 1~31 구간 과다 선택, 특히 1~12 (월) |
| 연속수 | `1 2 3 4 5 6` 같은 조합 |
| 등차수열 | `5 10 15 20 25 30` |
| 격자 패턴 | 마킹용지 위 직선·대각선 (같은 행/열 쏠림) |
| 끝자리 쏠림 | `1 11 21 31 41` |
| 행운의 숫자 | 7 및 7의 배수 선호 |

`STRATEGY_GAMES` 를 설정하면 이런 인기 조합을 회피한 번호를 생성합니다.
확률은 그대로지만, 1~3등에 당첨될 경우 분배 인원이 줄어 기대 수령액이 올라갑니다.
**이것이 이 프로젝트가 수행하는 유일하고 정직한 최적화입니다.**

## ✨ 주요 기능

- **단일 세션 자동화** — 브라우저 1개 / 로그인 1회로 전체 작업 수행
- **잔액 부족 시 자동 충전** — 구매 **전**에 잔액을 확보 (핵심)
- **OCR 키패드 인식** — 충전 시 랜덤 보안 키패드를 Tesseract 로 인식
- **기댓값 최적화 번호 생성** — 위 설명 참조
- **예치금 차감 기반 검증** — 화면 문구가 아니라 실제 차감액으로 구매 성공 판정
- **상세 텔레그램 알림** — 추첨번호 / 내 번호 / 일치 번호 / 등수를 게임별로 표시
- **DRY_RUN 모드** — 실제 구매 없이 절차만 검증
- **테스트 106개** — 순수 로직 회귀 테스트 + CI

## 🚀 시작하기

### 1. 저장소 Fork

### 2. GitHub Secrets 설정

**Settings → Secrets and variables → Actions → Secrets** 탭:

| Secret | 필수 | 설명 |
|---|---|---|
| `USER_ID` | ✅ | 동행복권 아이디 |
| `PASSWD` | ✅ | 동행복권 비밀번호 |
| `CHARGE_PIN` | ✅ | 간편충전 PIN 6자리 |
| `TELEGRAM_BOT_TOKEN` | – | 텔레그램 봇 토큰 |
| `TELEGRAM_CHAT_ID` | – | 텔레그램 Chat ID |

### 3. 구매 설정 (Variables)

**같은 화면의 Variables 탭** 에서 설정합니다. 비밀값이 아니므로 Secrets 가 아닙니다.

| Variable | 기본값 | 설명 |
|---|---|---|
| `STRATEGY_GAMES` | `5` | 기댓값 최적화 번호 게임 수 |
| `AUTO_GAMES` | `0` | 사이트 자동 선택 게임 수 |
| `MANUAL_NUMBERS` | `[]` | 직접 지정 번호 JSON |
| `LOTTO720_AMOUNT` | `5000` | 연금복권 구매액 (5,000원 단위) |
| `CHARGE_AMOUNT` | `10000` | 1회 충전액 (5000/10000/20000) |
| `MIN_BALANCE_FLOOR` | `10000` | 확보할 최소 잔액 |
| `ENABLE_LOTTO645` | `1` | 6/45 구매 활성화 |
| `ENABLE_LOTTO720` | `1` | 720+ 구매 활성화 |
| `LOTTO645_ENABLE_FROM` | (없음) | 이 날짜 이전엔 6/45 구매 안 함 |
| `LOG_LEVEL` | `INFO` | `DEBUG`/`INFO`/`WARNING`/`ERROR` |

> `STRATEGY_GAMES + AUTO_GAMES + MANUAL_NUMBERS` 합계는 **최대 5게임** 입니다.
> 초과하면 실행 전 검증에서 차단됩니다.

### 4. 첫 실행은 DRY_RUN 으로

**Actions → Lotto Purchase → Run workflow** 에서 `dry_run` 을 체크하면
실제 구매·충전 없이 로그인부터 구매 직전까지만 검증합니다.

문제가 없으면 체크를 해제하고 다시 실행하세요.

## 🔄 실행 순서

```
1. 로그인
2. 이전 회차 당첨번호 확인 + 내 구매번호 대조 → 텔레그램 알림
3. 잔액 확인 → 부족하면 충전 → 재확인      ← 구매보다 먼저!
4. 로또 6/45 구매 (전략번호 + 수동 + 자동)
5. 연금복권 720+ 구매 → 예치금 차감으로 검증
6. 결과 요약 알림
```

> **3단계가 4·5단계보다 먼저인 것이 중요합니다.**
> 이전 버전은 구매를 먼저 시도하고 충전을 나중에 했기 때문에,
> 잔액이 부족하면 이번 회차 구매가 전부 실패하고 충전은 다음 주용으로만
> 이뤄졌습니다.

## ⏰ 스케줄

| 워크플로우 | cron (UTC) | 실행 시각 (KST) |
|---|---|---|
| `purchase.yml` | `0 22 * * 0` | 매주 **월요일 07:00** |
| `check_results.yml` | `0 23 * * 6` | 매주 **일요일 08:00** |

> cron 은 UTC 기준입니다. KST = UTC + 9시간.

## 📱 텔레그램 알림

설정 방법은 [TELEGRAM_SETUP.md](TELEGRAM_SETUP.md) 참조.

당첨 결과 알림은 게임별로 다음을 표시합니다:

```
🎰 로또 1234회 추첨 결과

🎯 당첨 번호
03 11 19 27 35 43
보너스: 07

📋 내 구매 번호 (2게임)

1. [03] 11  19  40  44  45
   일치 3개 → 03 19 44

2.  05 [11][19][27] 41  45
   일치 3개 → 11 19 27
   🎉 5등 당첨 (5,000원)

🎉 당첨 요약
5등: 1장

확정 당첨금: 5,000원
```

- 일치한 번호는 `[ ]` 로 강조
- 당첨 집계는 **장수**로 표기 (이전 버전은 장수를 금액으로 잘못 표시)
- 4·5등은 고정 금액을 계산, 1~3등은 분배 후 확정임을 명시

## ⚠️ 주의사항

1. **간편충전만 지원** — 가상계좌 입금은 미지원
2. **OCR 정확도** — 키패드 인식률 약 90~95%. 실패 시 알림으로 통보됩니다
3. **중복 구매 방지** — 두 워크플로우 모두 `concurrency` 로 동시 실행을 차단합니다.
   단, 실패한 실행을 수동으로 재실행하면 재구매될 수 있으니 로그를 먼저 확인하세요
4. **디버그 산출물** — `DEBUG=1` 이면 `debug/` 에 스크린샷·HTML 이 저장됩니다.
   계정 정보와 잔액이 포함되므로 절대 커밋하지 마세요 (`.gitignore` 처리됨)
5. **사이트 점검 시간** — 매일 23:50~00:10 은 동행복권 점검 시간입니다

## 🐛 트러블슈팅

### 텔레그램 알림이 오지 않음
`TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` Secret 을 확인하세요.
미설정 시 실행 로그에 경고가 남습니다 (이전 버전은 조용히 실패했습니다).

### 연금복권 720+ 구매 실패
`DEBUG=1` 로 실행하면 게임 페이지의 클릭 가능한 요소 전체(id/class/onclick)가
로그에 출력되고 `debug/720_*.html` 이 저장됩니다.
사이트 DOM 이 변경된 경우 이 로그로 어떤 셀렉터가 바뀌었는지 특정할 수 있습니다.

### 구매 성공 여부가 불확실
720+ 는 예치금 차감액으로 판정합니다. 차감이 확인되지 않으면 성공 알림을
보내지 않습니다. 6/45 는 마이페이지 구매내역에서 **오늘 날짜**를 확인합니다.

### Playwright 브라우저 오류
```bash
playwright install --with-deps chromium
```
